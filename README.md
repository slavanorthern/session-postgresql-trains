
# Сессионный проект по PostgreSQL

**Выполнил:** Ожиганов В. В.  
**Вариант:** 5  
**Тема:** Пригородные поезда и станции

## 1. Описание проекта

Консольное приложение на Python для управления станциями и маршрутами пригородных электропоездов.

Проект разработан на основе базы данных из предыдущих домашних заданий по PostgreSQL. Используется направление Новосибирск-Главный — Тогучин.

Для выполнения сессионного задания используются две таблицы:

- `stations` — станции, их названия, тарифные зоны и порядок расположения на линии;
- `routes` — маршруты (отдельные рейсы) поездов с начальной и конечной станциями.

Согласно условиям варианта № 5, интерфейс работает только с начальной и конечной станциями. Промежуточные остановки, расписание и тарифы не входят в функциональность приложения.

Разные рейсы могут иметь одинаковые начальную и конечную станции. В интерфейсе они различаются по порядковому номеру строки.

## 2. Функциональные возможности

### Управление станциями

- Просмотр списка станций.
- Добавление новых станций.
- Изменение названия, тарифной зоны и порядка следования.
- Удаление станций с учетом связанных маршрутов.
- Подтверждение удаления связанных объектов.

### Управление маршрутами

- Просмотр маршрутов выбранной станции.
- Добавление маршрутов с выбором начальной и конечной станций.
- Удаление маршрутов по порядковому номеру строки.

### Проверка данных и безопасность

- Проверка обязательных полей.
- Проверка типов, диапазонов и длины введенных значений.
- Обработка ошибок PostgreSQL.
- Контроль уникальности и внешних ключей.
- Использование параметризованных SQL-запросов.
- Использование транзакций с откатом при ошибках.
- Отсутствие ввода суррогатных идентификаторов пользователем.

Постраничный просмотр и редактирование маршрутов относятся к дополнительным заданиям и не реализованы.

## 5. Установка и запуск

Инструкция предназначена для Windows с использованием Git Bash и VS Code.

### Шаг 1. Подготовка проекта

Скачайте ZIP-архив проекта и распакуйте его в отдельную папку.

Откройте эту папку в Visual Studio Code.

### Шаг 2. Установка зависимостей

Убедитесь, что Python установлен.

Откройте Git Bash в корневой папке проекта.

Создайте виртуальное окружение:

```bash
py -m venv .venv
```

Установите библиотеки:

```bash
./.venv/Scripts/python.exe -m pip install -r requirements.txt
```

### Шаг 3. Настройка подключения к PostgreSQL

Установите и запустите PostgreSQL.

В корневой папке проекта создайте файл `config.yaml` по образцу `config.example.yaml`.

Содержимое:

```yaml
dbname: postgres
user: postgres
password: "YOUR_PASSWORD"
host: localhost
dbtableprefix: "session_trains."
```

Замените `YOUR_PASSWORD` на пароль своего пользователя PostgreSQL.

Параметры подключения:

- `dbname` — название базы данных PostgreSQL;
- `user` — имя пользователя PostgreSQL;
- `password` — пароль пользователя;
- `host` — адрес сервера PostgreSQL;
- `dbtableprefix` — схема базы данных приложения.

Если на другом компьютере используются другое имя пользователя, пароль или база данных, соответствующие параметры необходимо изменить.

Например, если пользователь PostgreSQL называется `student`, база данных — `university`, а пароль — `my_password`, конфигурация будет следующей:

```yaml
dbname: university
user: student
password: "my_password"
host: localhost
dbtableprefix: "session_trains."
```

Поле `dbtableprefix` рекомендуется оставить без изменений.

**Важно:** файл `config.yaml` содержит учетные данные и исключен из Git с помощью `.gitignore`. Он не включается в архив для сдачи.

### Шаг 4. Создание таблиц

Откройте DBeaver и подключитесь к PostgreSQL.

Выберите базу данных, указанную в параметре `dbname`.

Откройте SQL-редактор и выполните файл `schema.sql` целиком.

Скрипт создаст отдельную схему `session_trains` и две таблицы:

- `stations`
- `routes`

Начальный набор данных включает 6 станций и 5 маршрутов.

Повторный запуск скрипта после начала работы с пользовательскими данными не требуется.

### Шаг 5. Запуск приложения

В Git Bash выполните:

```bash
./.venv/Scripts/python.exe main.py
```

При успешном подключении к PostgreSQL появится главное меню:

```text
ПРИГОРОДНЫЕ ПОЕЗДА: УПРАВЛЕНИЕ ДАННЫМИ

1 - просмотр станций
2 - добавление станции
3 - изменение станции
4 - удаление станции
5 - маршруты выбранной станции
9 - выход
```

Для выбора станций и маршрутов используются порядковые номера записей на экране. Вводить идентификаторы `station_id` и `route_id` не требуется.

## 6. Архитектура и безопасность

Приложение использует объектно-ориентированный подход.

Классы `StationsTable` и `RoutesTable` наследуются от базового класса `DbTable`.

SQL-запросы выполняются с помощью библиотеки psycopg2.

Пользовательские значения передаются отдельно от текста SQL через параметры запросов. Имена схемы и таблиц формируются с использованием `psycopg2.sql.Identifier`.

Транзакции позволяют отменить изменения при возникновении ошибки PostgreSQL.

Операции удаления связанных объектов требуют подтверждения пользователя.
